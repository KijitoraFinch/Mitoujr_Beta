# 拡張

拡張は固定済みの Observation から Region を解決し、Link を取り込み、Region の同一性と包含を比較する。
Core は拡張に必要な Observation を渡し、拡張の判定と失敗を結果に反映する。
利用者の拡張を独立したプロセスとして呼び出し、構造化した入出力で同じ操作に参加させる。

Resource の観測と Observation の解釈を外部拡張が提供する。Link と注釈の正本は Core が専用に管理する。
Region の内部表現と、その同一性・包含の判定は拡張が受け持つ。
複数の拡張が共通の Region の表現を扱える。
取り込みは、指定された Observation から Link とその中の位置を返す。
Core が取り込み元の Observation と拡張の版を正本に記録する。
生成では拡張が選択された Link の表現を返す。Core は提案を Observation として固定し、
同じ拡張による読み戻しで Link と注釈の保持を確認する。適用時の内容照合は Core と提供元が行う。

解決・比較に使う LS やプロジェクト設定などの外部状態と、結果のキャッシュは拡張が管理する。
Core は解決・比較を拡張に要求し、各解決で渡した Observation を結果に記録する。
現在の状態を扱い、操作中は関連ファイルが外部から変更されないと仮定する。
Observation は操作中の入力として保持し、履歴はバージョン管理システムや Resource の提供元に任せる。
拡張へ渡す内容は一時ファイルに置き、拡張プロセスの終了後に削除する。
拡張の応答が失敗した場合は、その理由を呼び出し元に返す。
必要な Observation を渡す処理と比較の呼び出しは、Link 数が増えても実用的に動くようにする。

解決中の拡張は必要な Resource を要求し、その Observation だけを受け取る。解決と Resource の観測を同じ拡張が
提供する場合も、その要求に応答できる。Core が提供元への観測要求と読み取りの記録を受け持ち、拡張は
固定済みの内容と不在を解釈する。入力へのアクセスと外部プロセスとの通信を分けて扱う。

拡張プロセスの所有者を CLI 操作の期間に置き、観測セッションが変わっても終了処理を
追跡できるようにする。通信は Tokio の非同期 I/O と期限付きの待機で行う。
通常終了では入力を閉じて終了を待ち、中断・通信破損・期限超過ではプロセス群を終了する。
終了処理も明示的に待機し、結果を呼び出し元へ返す。
