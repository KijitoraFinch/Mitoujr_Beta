# 拡張

拡張は観測済みの内容から領域と宣言を読み取り、領域の同一性と包含を比較する。
Core は拡張に必要な観測を渡し、拡張の判定と失敗を結果に反映する。
利用者の拡張を独立したプロセスとして呼び出し、構造化した入出力で同じ操作に参加させる。

すべての形式と資源の観測を外部拡張が提供する。Core は領域の内部表現を解釈せず、
拡張に同一性と包含の判定を委ねる。複数の拡張が共通の領域表現を扱える。
宣言は意味上の起点に加えて元の記載位置を保持する。編集はその記載を変更する案を返し、
適用時の内容照合は Core が行う。

一つの操作で使う固定済みの観測と解釈を、続く問い合わせでも再利用できる。
拡張の応答が失敗した場合は、その理由を呼び出し元に返す。
必要な観測を渡す処理と比較の呼び出しは、リンク数が増えても実用的に動くようにする。

解決中の拡張は必要な資源を要求し、その観測だけを受け取る。解決と資源の取得を同じ拡張が
提供する場合も、その要求に応答できる。Core が資源の取得と依存の記録を受け持ち、拡張は
固定済みの内容と不在を解釈する。入力へのアクセスと外部プロセスとの通信を分けて扱う。

拡張プロセスの所有者を CLI 操作の期間に置き、観測セッションが変わっても終了処理を
追跡できるようにする。通信は Tokio の非同期 I/O と期限付きの待機で行う。
通常終了では入力を閉じて終了を待ち、中断・通信破損・期限超過ではプロセス群を終了する。
終了処理も明示的に待機し、結果を呼び出し元へ返す。
